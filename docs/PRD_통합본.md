# 돌봄 분석을 위한 조기 감지 서비스 — PRD (통합본)

- 팀명: 헬포 (Helpo)
- 팀원: 송수한, 최용찬, 김의정, 신하영, 백정우
- 버전: 2026-08-18 통합 (PRD 수정본 + 2·3·4강 워크시트 + 8/12 데모 검증 반영) → 2차 개정 (가족 구조·일정·수익모델·음성 AI 방향 확정 반영)

## 한 줄 소개

독거 고령자가 매일 간단한 안부 체크(지병 관련 체크, 컨디션, 음성 답변)를 남기면 AI가 인지기능 저하 등 이상 신호를 조기에 감지해 자녀에게 위험도에 따라 알리고, 영상 편지로 정서적 연결까지 함께 유지하는 조기 감지 서비스.

## 문제정의

독거 고령자는 혼자 지내는 시간이 길어 돌봄 공백이 생기기 쉽고, 본인이나 자녀 모두 평소와 다른 이상 신호(특히 인지기능 저하처럼 스스로 알아차리기 어려운 변화)를 조기에 판별하기 어렵다. 자녀는 생업 등의 이유로 매일 방문·통화하기 어렵고, 고령자 본인도 초기 변화를 자각하지 못하는 경우가 많아, 문제가 뚜렷해진 뒤에야 뒤늦게 발견되는 경우가 많다.

## 타겟

| 구분 | 대상 | 행동 |
|---|---|---|
| 메인 | 독거 고령자 본인 | 매일 서비스를 통해 스스로 안부를 남긴다 |
| 서브 | 자녀(보호자) | 안부 체크·음성 데이터·위험도 알림을 확인하고, 필요 시 직접 연락하거나 방문한다 |

### 디지털 활용·가족 소통 수준 기준 세분화 — "중" 계층 타겟

독거 고령자를 **휴대폰 등 디지털 기기 수용도**와 **자녀와의 소통 수준**을 기준으로 상/중/하 3단계로 나눴을 때, 이 서비스는 **중간 계층**을 타겟으로 한다.

| 계층 | 특징 | 타겟 여부 |
|---|---|---|
| 상 | 휴대폰 등 문명을 매우 잘 받아들이고, 이미 영상통화 등으로 자녀와 소통이 매우 잘 되는 분들 | ✗ (이미 자녀와 직접 소통이 원활해 조기 감지 서비스의 효용이 낮음) |
| **중** | 휴대폰을 어느 정도 사용할 수 있고, 자녀와도 어느 정도는 소통이 가능한 계층 | **✓ 메인 타겟** |
| 하 | 휴대폰을 아예 사용하지 못하거나, 국가적 도움을 받으며 자녀와 소통 자체가 단절된 분들(보호자가 국가 지원이거나 휴대폰이 없는 수준일 수 있음) | ✗ (앱 기반 온보딩 자체가 불가능 — 국가 복지 서비스 영역) |

**근거**: "상" 계층은 이미 영상통화 등으로 자녀와 활발히 소통하고 있어 별도의 안부 체크·위험 알림 서비스가 주는 부가가치가 작다. "하" 계층은 휴대폰조차 다루기 어렵거나 이미 국가 지원 체계에 있어, 앱을 통한 링크 접속·음성 응답 자체가 기술적으로 불가능에 가깝다. 헬포는 "휴대폰은 어느 정도 쓸 수 있지만 자녀와의 소통은 충분하지 않아 돌봄 공백이 생기는" 중간 계층에서 가장 큰 가치를 만들어낸다.

**영향**:
- **온보딩 난이도**: 중간 계층 기준으로 설계 — 지나치게 복잡한 기술 조작(다단계 인증, 세밀한 설정)은 피하고, 초대 링크 클릭만으로 접속 가능한 현재 흐름이 이 타겟에 적합하다.
- **문항/UX 톤**: 자녀와의 소통이 "어느 정도는" 되는 계층이므로, 완전히 소통이 단절된 취약계층 대상 문구(과도하게 보호적인 톤)보다는 일상적인 안부 확인 톤을 유지한다.
- **접근성 기능**(글씨 크기 확대, TTS)은 유지하되, "하" 계층(비휴대폰 사용자)까지 포괄하는 것을 목표로 하지 않는다 — 이는 범위 밖으로 명확히 한다.

## 가족 구조 — 1가족 : N어르신 (확정)

기존 3강 워크시트는 "1고령자-1가족 단위로 한정, 다대다 구조는 다루지 않는다"고 정의했으나, 8/12 데모의 대상자 목록 화면은 이미 자녀 1인이 여러 어르신(부모·시부모 등)을 관리하는 화면을 보여주고 있었다. 팀 논의 결과 **1가족(자녀 계정) : N어르신** 구조를 공식 스코프로 확정한다.

- **데이터 모델 영향**: 가족계정 1 — N 어르신프로필 관계로 설계 (상세는 [데이터스키마.md](데이터스키마.md) 참고)
- **알림 라우팅 영향**: 위험도 알림은 어르신 단위로 발생하고, 대상자 목록 화면에서 여러 어르신을 우선순위(안전/위험/심각)로 한눈에 확인
- **온보딩 영향**: 가족 계정은 "어르신 등록"을 반복 가능한 단계로 취급 — 최초 등록 후에도 "어르신 추가" 흐름으로 계속 인원을 늘릴 수 있다

## 차별점 (회의에서 강조된 포지셔닝)

- 기존 서비스는 복지 정보 안내·응급 알림·돌봄 신청처럼 기능이 분절되어 있으나, 헬포는 건강과 주거 신호를 함께 보고 위험 신호를 먼저 찾아내 가족이 바로 이해할 수 있는 화면으로 연결한다.
- **카카오톡 같은 범용 메신저 대비**: 지병 맞춤 질문 + 자동 위험도 산정 + 가족용 우선순위 대시보드가 구조화되어 있어, 매일 직접 챙기지 않아도 이상 신호만 걸러서 받을 수 있다.
- **"진단이 아니라 확인"** — AI는 진단을 내리지 않고 확인이 필요한 변화만 짚어준다. 법적·신뢰 리스크를 최소화하면서 부담 없는 톤을 유지하는 것이 핵심 포지셔닝이다.

### 경쟁 서비스 비교

| 서비스 | 기능 | 타겟 | 가격 | 헬포 대비 차별점 |
|---|---|---|---|---|
| 카카오톡(영상통화) | 범용 메신저·영상통화 | 전 연령 | 무료 | 구조화된 안부 체크·위험도 산정·우선순위 알림이 없음. 자녀가 매번 직접 확인해야 함 |
| 지자체 안부확인 서비스 (독거노인 안심콜 등) | 전화 기반 정기 안부 확인, 응급 연계 | 국가 지원 대상 고령자 | 무료(공공) | 응급 신고·전화 중심이라 정서적 연결(영상편지) 요소가 없고, 자녀에게 직접 데이터가 공유되지 않음 |
| 민간 케어콜 서비스 | AI 전화 콜, 간단 안부 질문 | 유료 가입 고령자 | 유료 | 음성 통화 중심으로 지병별 맞춤 질문이나 자녀용 대시보드가 약함 |
| 복지로(정부 포털) | 복지 정보·신청 창구 | 전 국민 | 무료(공공) | 정보 안내 중심으로 실시간 이상 신호 감지 기능 자체가 없음 |

헬포는 "지병 맞춤 질문 + 위험도 산정 + 가족 대시보드 + 정서적 영상편지"를 하나의 흐름으로 묶은 유일한 조합이라는 점이 차별점이다.

## 핵심 가치

- 고령자 본인이 매일 짧은 시간만 투자해 안부를 남기면, AI가 사람이 놓치기 쉬운 이상 신호를 조기에 감지한다.
- 자녀는 매일 직접 확인하지 않아도, 위험도가 실제로 높아졌을 때만 단계적으로 알림을 받는다.
- 영상 편지 기능으로 고령자와 자녀 사이의 정서적 연결을 함께 유지한다.
- AI는 진단을 내리지 않는다. 확인이 필요한 변화를 먼저 짚어주는 역할에 머문다.

## 핵심 기능 (MVP 확정, 4강 코칭 반영)

1. **일일 안부 체크**: 등록된 지병 목록 기반 맞춤 체크리스트 6~8문항 (선택형 응답)
2. **말하기 안부**: 자유 음성 1문항(가족에게 한마디) — STT API로 텍스트 변환 후 규칙 기반 휴리스틱(발화 속도·침묵 비율·응답 지연)으로 인지기능 신호 후보를 산출. TTS로 질문을 읽어주어 거부감 완화
3. **위험도 분석 및 알림**: 지병별 가중치 + 무응답 시간/복약 누락/연속 외출 없음 등을 근거로 안전·위험·심각 3단계 산정. 경미한 변화는 알림만, 심각한 변화는 알림+대응 안내(직접 신고는 하지 않음)
4. **영상 편지**: 고령자·자녀 상호 교환. 안부 체크를 완료해야 그날 도착한 편지가 열리는 구조로 꾸준한 참여를 유도
5. **초대 링크 기반 온보딩**: 어르신은 앱 설치·계정 생성 없이 1회용 링크(기기당 1회 개봉 후 만료)로 접속

## 사용자 흐름

1. 자녀가 계정을 만들고 어르신 정보·지병을 등록한다 (어르신은 반복 등록 가능, 1가족:N어르신).
2. 지병에 따라 자동 구성된 초대 링크를 어르신에게 문자로 보낸다.
3. 어르신이 링크로 접속해 매일 체크리스트+음성 답변을 남긴다.
4. STT·규칙 기반 휴리스틱이 체크리스트·음성 데이터를 과거 기록과 비교해 위험도를 산정한다.
5. 위험도에 따라 자녀에게 단계적으로 알림이 가고, 자녀는 확인·전화·방문 등으로 대응한다.
6. 안부 체크와 별개로 언제든 영상 편지를 주고받는다.

## MVP 범위 확정 (4강 워크시트 · MVP 범위표 기준)

### 필수 (이번에 만든다)
- 접근성: 글씨 크기 확대 가능 기능, 어르신 눈높이 단어 사용
- 계정/온보딩: 로그인 및 자동 로그인 체크박스, 계정 만들기(전화번호 인증→비밀번호→어르신 정보→지병 선택), 비밀번호 확인, 계정 찾기, 초대 링크를 통한 가족 연결, **어르신 추가(반복 등록, 1:N 구조)**
- 내비게이션: 모든 선택지에 뒤로가기 버튼
- 안부 체크: 지병 선택에 따라 질문 선택지가 달라짐, 맞춤 질문 음성 응답(6~8개), 응답은 정해진 선택지 기반
- 영상 편지: 주제를 제시하는 방식으로 시작(주제 여러 가지), 확인 후 전송, 촬영 안내 멘트, 마지막 홈버튼
- 대상자 관리: 어르신 정보(**생년월일로 확정** — 화면에는 계산된 나이를 표시하되 저장은 생년월일 기준), 앓고 있는 병(사전 정의 칩 + **직접 입력 1줄 텍스트** 확정), 초대하기 버튼, 대상자 목록 우선순위 표시(안전/위험/심각 구분), 목록에서 관계 또는 별명 설정(※ 관계 필드는 1차 유지, 성별 필드 추가는 제안 — 팀 최종 확인 필요), 시간 선택 기능
- 기록/차별점: 꺾은선 그래프 기록, 장수기록(연속 참여일), 영상통화 저장/다운로드 기능, 음성과 영상 기능 합치기
- 데이터/보안: 개인정보 동의

### 나중 (아이디어톤 이후)
- 앱/클라우드 제공

### 버림 (하지 않는다)
- AI의 안색 또는 표정 진단 — 개인정보 침해 우려, 조명에 따라 판별이 불가능하여 기술적으로도 신뢰하기 어려움
- 외부 데이터 사용을 줄이는 방향으로 설계 (자체 체크리스트·음성 데이터 중심)
- 자체 ML 모델 학습 — STT API + 규칙 기반 휴리스틱으로 대체 (팀 리소스·일정 고려)

## 수익모델 / 지속가능성

**전면 무료 서비스**로 진행한다. 사회문제 해결을 우선순위로 두고, 이번 단계에서는 구독·프리미엄 등 결제 기능을 만들지 않는다. 지자체·복지관과의 협력을 통한 향후 지속가능성 모델은 현재 스코프에서 다루지 않으며, 필요 시 추후 별도 논의한다.

## 확정 화면 구성

|---|---|
| 메인(로그인) | 2 |
| 고령자 | 5 |
| 보호자(자녀) | 6 |

## 범위 밖

- 의료적 진단·처방은 제공하지 않는다.
- 서비스가 직접 119 등 응급기관에 신고하지 않는다.
- 웨어러블·IoT 센서 연동은 포함하지 않는다.
- 휴대폰을 전혀 다루지 못하거나 자녀와의 소통이 이미 단절된 "하" 계층은 타겟에서 제외한다 (국가 복지 서비스 영역, 앱 기반 온보딩 불가능).
- 유료 결제·구독·프리미엄 기능은 다루지 않는다 (전면 무료 방침).
- 자체 음성 AI 모델 학습은 다루지 않는다 (STT API + 규칙 기반 휴리스틱으로 대체).
