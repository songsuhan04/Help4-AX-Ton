# 기능설계서 — 헬포 (Helpo)

- 기준 자료: 4강 워크시트(MVP 범위표, 멘토 코칭 메모), 3강 워크시트(화면 구조 문서), 8/12 데모 실제 동작 검증, PRD_통합본.md 2차 개정(가족 구조·수익모델·음성 AI 방향 확정)
- 구성: ⓪ 기술 스택/아키텍처 ① 기능 분류(필수/나중/버림) ② 기능별 상세 명세 ③ 위험도 판정 로직 ④ 데이터 모델(별도 문서 링크) ⑤ 비기능 요구사항 ⑥ 오픈 이슈

## 0. 기술 스택 / 아키텍처 (제안 — 팀 최종 확인 필요)

3~4주 일정에 맞춰 빠르게 구축 가능한 구성을 제안한다.

| 레이어 | 제안 | 비고 |
|---|---|---|
| 프론트엔드 | React 기반 웹(반응형) | 기존 8/12 데모(index_0812.html)가 React 기반이라 그대로 확장 가능 |
| 백엔드/DB | 경량 BaaS (예: Firebase 또는 Supabase) | 자체 서버 구축 없이 인증·DB·파일 스토리지(영상/음성)를 빠르게 확보 |
| 음성 인식(STT) | 한국어 특화 STT API (예: 네이버 클로바 스피치, 대안: OpenAI Whisper) | 어르신 발화 특성(속도 느림, 방언 등) 고려해 한국어 특화 엔진 우선 검토 |
| 인지기능 신호 분석 | 자체 ML 모델 없이 STT 결과에 규칙 기반 휴리스틱 적용 | §2.2 참고. 팀 리소스·일정상 자체 모델 학습은 범위 밖 |
| 호스팅 | Vercel/Netlify 등 정적 호스팅 + BaaS 조합 | 별도 서버 운영 부담 최소화 |

※ 위 항목은 모두 "제안"이며, 실제 팀 역량(누가 백엔드를 맡을 수 있는지 등)에 따라 조정이 필요하다.

## 1. 기능 분류

### 필수 (이번에 만든다)

| 분류 | 기능 |
|---|---|
| 접근성 | 글씨 크기 확대, 어르신 눈높이 단어 사용, TTS(읽어주기) |
| 계정/온보딩 | 로그인, 자동 로그인 체크박스, 계정 만들기(전화번호 인증→비밀번호→어르신 정보→지병 선택), 비밀번호 확인, 계정 찾기, 초대 링크를 통한 가족 연결(1회용), **어르신 추가(반복 등록, 1가족:N어르신)** |
| 내비게이션 | 모든 화면에 뒤로가기 버튼 |
| 안부 체크 | 지병 선택 기반 맞춤 문항(6~8개), 선택형 응답, 말하기 안부(자유 음성 1문항) |
| 위험도 분석 | 체크리스트·응답 시간·음성 데이터 기반 위험도 산정, 안전/위험/심각 3단계 알림 |
| 영상 편지 | 주제 제시형 시작(주제 여러 가지), 확인 후 전송, 촬영 안내 멘트, 저장/다운로드, 안부체크 완료 후 열람되는 언락 구조 |
| 대상자 관리 | 어르신 정보(생년월일 확정, 앓고 있는 병 - 사전 정의 + 직접 입력 확정), 초대하기 버튼, 목록 우선순위 표시(안전/위험/심각), 관계·별명 설정(성별 필드는 제안, 팀 확인 대기), 안부 시각 선택 |
| 기록/차별점 | 꺾은선 그래프 기록, 장수기록(연속 참여일수), 음성·영상 기능 통합 |
| 데이터/보안 | 개인정보 동의 |

### 나중 (아이디어톤 이후)
- 앱/클라우드 제공

### 버림 (하지 않는다)
- AI의 안색·표정 진단 — 사유: 개인정보 침해 우려, 조명 조건에 따라 판별 불가능해 신뢰도 확보가 어려움
- 외부 데이터 의존 최소화 방향 유지
- 자체 ML 모델 학습 — STT API + 규칙 기반 휴리스틱으로 대체
- 유료/프리미엄 기능 — 전면 무료 서비스 방침 (사회문제 해결 우선, [PRD_통합본.md](PRD_통합본.md) 수익모델 절 참고)

## 2. 기능별 상세 명세

### 2.1 지병 맞춤 안부 체크
- **트리거**: 어르신이 매일 접속(또는 알림 수신 후 접속)
- **입력**: 등록된 지병 목록, 오늘 날짜
- **처리 로직**: 지병별로 정의된 문항 풀에서 6~8개를 조합 (공통 문항: 복약, 식사, 외출 여부 + 지병별 특화 문항: 예) 고혈압→두통/어지럼, 당뇨병→손발 저림, 관절염→무릎 통증)
- **출력**: 선택형 응답 결과 저장
- **예외/제약**: 오늘 건너뛰기 가능(말하기 안부 기준 확인됨), 무응답 시 위험도 로직에 반영

### 2.2 말하기 안부 (음성) — STT + 규칙 기반 휴리스틱 확정
- **트리거**: 체크리스트 응답 완료 후 마지막 순서
- **입력**: 어르신의 음성 답변(자유 발화, 가족에게 한마디 형태)
- **처리 로직**:
  1. STT API로 음성을 텍스트(transcript)로 변환
  2. 텍스트·음성 신호에서 규칙 기반 지표 계산: **발화 속도**(어절수 ÷ 소요 시간(분)), **침묵 비율**(무음 구간 ÷ 전체 발화 시간), **응답 지연**(질문 표시 시각 ~ 발화 시작 시각)
  3. 전체 인구 평균이 아닌 **해당 어르신의 최근 7일 평균 대비 이탈 정도**로 이상 신호 판단 (개인차가 큰 지표이므로 개인 기준선 비교가 더 신뢰도 높음)
- **출력**: 음성 원본은 가족에게도 함께 전송, 규칙 기반 판정 결과는 위험도 산정(§2.3)에 반영
- **예외/제약**: 오늘 건너뛰기 가능, 천천히 말해도 되도록 UX상 재촉하지 않음. STT 인식률이 낮은 경우(사투리·틀니 등) 애매한 판정은 "위험"으로 낮춰 오탐보다 재확인을 유도 (§리스크 레지스터 참고)

### 2.3 위험도 분석 및 알림
- **트리거**: 매일 체크리스트·음성 데이터 수집 완료 시 자동 실행
- **입력**: 오늘 응답, 과거 기록, 지병별 가중치
- **처리 로직** (⚠️ 아래 수치는 데모/설명용 예시값이며, 실제 임상적 근거가 확보되기 전까지는 팀이 합의한 잠정 규칙임 — §3 참고):
  - 복약 누락 → 고혈압 보유자는 위험 1.5배로 가중
  - 식사 거름 → 당뇨병 보유자는 위험 2.4배(저혈당 위험)로 가중
  - 외출 없음 → 관절염 보유자는 위험 요인으로 보지 않음(운동 부족과 무관하게 판단)
  - 응답 없음이 일정 시간(예: 7시간) 지속되거나, 외출 없음이 연속(예: 3일) 될 경우 알림 트리거
- **출력**: 안전 / 위험 / 심각 3단계 등급 + 사유 문구(예: "일곱 시간 동안 대답이 없습니다")
- **알림 정책**: 경미(위험) → 자녀에게 알림만 / 심각 → 알림 + 대응 안내("직접 연락해보세요", "필요 시 119 등 도움을 요청하세요") 제공. 서비스가 직접 신고하지는 않음
- **가족 대응 액션**: "전화하기" 또는 "확인했어요"로 상태 종료 처리 (※ "진단이 아니라 확인" 포지셔닝에 맞춰 확정 액션이 아닌 확인 액션으로 설계)
- **1가족:N어르신 처리**: 위험도는 어르신 단위로 개별 산정되며, 대상자 목록 화면에서 어르신별 카드로 분리 표시해 여러 어르신의 알림이 섞이지 않도록 한다

### 2.4 영상 편지
- **트리거**: 가족 또는 어르신이 임의 시점에 시작
- **입력**: 짧은 영상(주제 제시형, 주제는 여러 개 중 선택/랜덤)
- **처리 로직**: 촬영 전 안내 멘트(정면을 봐주세요 등) 제공 → 확인 후 전송
- **출력**: 상대방에게 알림 전송. 어르신에게 온 편지는 그날 안부 체크를 완료해야 열람 가능(참여 유도 장치)
- **부가 기능**: 저장/다운로드, 음성 기능과의 통합

### 2.5 초대 링크 온보딩 (예외 처리 포함)
- **트리거**: 가족이 어르신 등록·지병 선택 완료 후 발급
- **입력**: 어르신 전화번호(문자 발송용)
- **처리 로직**: 1회용 토큰 생성, 최초 개봉 기기에 종속(다른 기기에서 재사용 불가), 한 번 연결되면 계정처럼 계속 유지
- **출력**: 어르신은 별도 계정 생성 없이 링크 클릭만으로 접속
- **예외 처리**:

| 상황 | 감지 방법 | 처리 |
|---|---|---|
| 휴대폰 분실 | 가족이 대상자 상세 화면에서 "재초대" 요청 | 기존 토큰 무효화 후 새 1회용 링크 발급, 문자 재발송 |
| 기기 변경(새 폰 구매) | 새 기기에서 기존 링크 접속 시 device_fingerprint 불일치 | 기존 링크는 만료 처리, 가족이 재초대해야 새 기기에서 연결 |
| 초대 링크 유출/오전달 | 등록되지 않은 기기에서 최초 개봉 시도 | 최초 개봉 기기에만 종속되므로 이후 다른 기기 접근은 자동 차단 |
| 링크 만료 후 미접속 | 발급 후 일정 기간 미개봉 | 가족에게 "아직 연결되지 않았어요" 안내, 재발송 유도 |

## 3. 위험도 판정 로직 요약표

⚠️ **아래 수치는 데모/설명용 예시값이며, 실제 임상적 근거 확보 전까지는 팀이 합의한 잠정 규칙이다.** 실제 서비스 전환 시 전문가 검증이 필요하다 (오픈 이슈 참고).

| 신호 | 조건 | 가중 대상 | 결과 |
|---|---|---|---|
| 복약 누락 | 어제 복약 체크 실패 | 고혈압 보유자 | 위험 1.5배 |
| 식사 결식 | 오늘 식사 체크 실패 | 당뇨병 보유자 | 위험 2.4배(저혈당 우려) |
| 외출 없음 | 연속 외출 없음 | 관절염 보유자 | 가중하지 않음(정상 범위로 처리) |
| 무응답 | 일정 시간 이상 응답 없음(예: 7시간) | 전체 | 위험/심각 알림 트리거 |
| 연속 외출 없음 | 예: 사흘 연속 | 전체 | 위험 알림 트리거 |

상세 엔티티·필드·관계 정의는 [데이터스키마.md](데이터스키마.md)로 분리했다 (1가족:N어르신 구조 확정을 반영한 정식 스키마).

## 5. 비기능 요구사항

- **접근성**: 글씨 크기 확대 가능, 고령자 눈높이 단어 사용, TTS 지원(AI 음성 기능에 대한 거부감 완화 목적)
- **개인정보 보호**: 개인정보 동의 절차 필수, 안색·표정 등 민감 생체 정보 분석은 제외
- **신뢰성**: AI는 "진단"이 아닌 "확인 필요 신호"로만 표현 — 법적/신뢰 리스크 관리
- **보안**: 초대 링크 1회용·기기 종속으로 무단 접근 방지
- **비용**: 전면 무료 서비스 — 결제·구독 관련 기능/인프라는 구축하지 않는다

## 6. 오픈 이슈 (기능 관점)

1. "관계" 필드 유지 + "성별" 필드 추가(제안)가 실제 데이터 모델·화면에 반영될지 팀 최종 확인 필요
2. 대상자 목록의 우선순위를 자동 산정 등급 그대로 둘지, 사용자가 수동으로 재조정할 수 있게 할지 여부
3. 무응답 임계 시간(7시간), 연속 외출 없음 기준(3일) 등 구체적 파라미터의 근거 자료 필요(현재는 팀 합의 잠정값)
4. STT API 벤더 최종 선정(클로바 스피치 vs Whisper 등) — 비용·한국어 정확도 비교 필요
