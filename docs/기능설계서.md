⚠️ **API 키 등 민감 정보 취급 원칙**: Supabase/Resend/Gemini API 키는 절대 코드에 하드코딩하거나 커밋하지 않는다. 모두 환경변수(`.env`는 `.gitignore`에 포함, Vercel은 Project Settings → Environment Variables)로만 관리한다.

## 2. 기능별 상세 명세

### 2.1 지병 맞춤 안부 체크 (✅ Gemini 동적 생성으로 변경, 실사용 피드백 반영)
- **트리거**: 어르신이 매일 접속(또는 알림 수신 후 접속)
- **입력**: 등록된 지병 목록, 오늘 날짜, 최근 3일간 이미 사용한 질문 목록(중복 방지용)
- **처리 로직**: `api/generate-questions.ts`가 지병 목록+최근 질문을 Gemini에 전달해 6~8개 문항을 매일 새로 생성. 공통 문항(복약·식사·외출 여부)은 매번 표현을 다르게, 지병별 특화 문항(고혈압→두통/어지럼, 당뇨병→손발 저림, 관절염→무릎 통증 등)을 최소 1개씩 포함하도록 프롬프트로 지시. **질문마다 답변 선택지도 질문 성격에 맞게 2~3개 생성**(예: 기분을 묻는 질문은 "좋아요/보통이에요/안 좋아요")하여 모든 문항을 네/아니요로만 묻던 기존 방식의 한계를 해소. `GEMINI_API_KEY` 미설정이나 호출 실패 시 지병별 고정 문항(네/아니요)으로 조용히 대체
- **출력**: 생성된 질문+선택지 세트를 `daily_checkin.questions`에 즉시 캐시(같은 날 새로고침해도 동일 질문 유지), 선택형 응답 결과는 `daily_checkin.answers`에 저장
- **예외/제약**: 오늘 건너뛰기 가능(말하기 안부 기준 확인됨), 무응답 시 위험도 로직에 반영

### 2.2 말하기 안부 (음성) — Gemini 기반으로 변경 (3차 개정)
- **트리거**: 체크리스트 응답 완료 후 마지막 순서
- **입력**: 어르신의 음성 답변(자유 발화, 보호자에게 한마디 형태)
- **처리 로직**:
  1. 음성 파일을 **Gemini API**에 직접 전달해 분석 요청 (별도 STT 변환 단계 없이 멀티모달 입력으로 처리)
  2. Gemini 응답에서 발화 속도·침묵 비율·응답 지연 등 정량 지표 또는 이에 준하는 소견을 추출 (⚠️ Gemini가 이런 정량 수치를 안정적으로 반환하는지는 검증 전 — §6 오픈 이슈 2번 참고)
  3. 전체 인구 평균이 아닌 **해당 어르신의 최근 7일 평균 대비 이탈 정도**로 이상 신호 판단 (개인차가 큰 지표이므로 개인 기준선 비교가 더 신뢰도 높음)
- **출력**: 음성 원본은 보호자에게도 함께 전송(**✅ 대상자 상세 화면에서 실제로 재생/청취 가능**), Gemini 분석 결과는 위험도 산정(§2.3)에 반영
- **예외/제약**: 오늘 건너뛰기 가능, 천천히 말해도 되도록 UX상 재촉하지 않음. 분석 신뢰도가 낮은 경우(사투리·틀니 등) 애매한 판정은 "위험"으로 낮춰 오탐보다 재확인을 유도 (§리스크 레지스터 참고)

### 2.3 위험도 분석 및 알림 (✅ 실제 연결 완료)
- **트리거**: 안부 체크 완료 시(`api/assess-risk.ts`), 음성 분석 완료 시(`api/analyze-voice.ts`) — 둘 다 `lib/riskScoring.ts`의 동일한 계산을 다시 실행해 그날의 등급을 최신 상태로 갱신
- **입력**: 오늘 응답(category+severity 태그), 지병 목록, 오늘 음성 분석 상태
- **처리 로직** (⚠️ 아래 수치는 데모/설명용 예시값이며, 실제 임상적 근거가 확보되기 전까지는 팀이 합의한 잠정 규칙임 — §3 참고):
  - 복약 누락 → 고혈압 보유자는 위험 1.5배로 가중
  - 식사 거름 → 당뇨병 보유자는 위험 2.0배(저혈당 위험)로 가중
  - 외출 없음 → 관절염 보유자는 위험 요인으로 보지 않음(운동 부족과 무관하게 판단)
  - 음성 분석 실패(`analysis_status='failed'`) → +1점(애매한 판정은 위험 쪽으로)
  - **✅ 무응답 7시간 알림**: `api/check-no-response.ts`(Vercel Cron, 매일 21:00 KST)가 안부 시각으로부터 7시간이 지나도록 오늘 안부체크가 없는 어르신을 찾아 "위험" 등급으로 기록. ⚠️ Hobby 플랜은 크론이 하루 1번뿐이라 정확히 7시간째가 아니라 하루 한 번 몰아서 확인함(기본 안부 시각 08:00 기준으로는 충분히 늦은 시간)
  - **미구현(오픈 이슈)**: 외출 없음 연속(예: 3일) 알림 트리거 — 오늘 체크인 시점에 최근 며칠 답변을 함께 보면 되어 cron 없이도 가능하지만 아직 미구현
- **출력**: 안전 / 위험 / 심각 3단계 등급 + 사유 문구(예: "복약을 놓치셨어요(고혈압)")
- **알림 정책**: 경미(위험) → 보호자에게 알림만 / 심각 → 알림 + 대응 안내("직접 연락해보세요", "필요 시 119 등 도움을 요청하세요") 제공. 서비스가 직접 신고하지는 않음
- **보호자 대응 액션**: "전화하기" 또는 "확인했어요"로 상태 종료 처리 (※ "진단이 아니라 확인" 포지셔닝에 맞춰 확정 액션이 아닌 확인 액션으로 설계). **✅ "전화하기"는 앱 내 통화가 아니라 어르신 등록 시 입력한 전화번호로 `tel:` 링크를 열어 기기의 실제 전화 앱으로 연결**(전화번호 미등록 시 버튼 비활성화)
- **1가족:N어르신 처리**: 위험도는 어르신 단위로 개별 산정되며, 대상자 목록 화면에서 어르신별 카드로 분리 표시해 여러 어르신의 알림이 섞이지 않도록 한다

### 2.4 영상 편지 (Gemini 영상 분석 범위 미확정)
- **트리거**: 보호자 또는 어르신이 임의 시점에 시작
- **입력**: 짧은 영상(주제 제시형, 주제는 여러 개 중 선택/랜덤)
- **처리 로직**: 촬영 전 안내 멘트(정면을 봐주세요 등) 제공 → 확인 후 전송
- **출력**: 상대방에게 알림 전송. 어르신에게 온 편지는 그날 안부 체크를 완료해야 열람 가능(참여 유도 장치). **✅ 어르신이 보낸 편지도 보호자 화면(대상자 상세)에서 목록/재생 가능 — 양방향 열람**
- **✅ 보호자가 보낸 편지 확인/삭제**: 대상자 상세 화면에 "내가 보낸 영상편지" 목록을 추가해, 촬영을 잘못한 경우 보호자가 직접 확인하고 삭제할 수 있다(영상 파일+DB 행 모두 삭제, 되돌릴 수 없음을 확인 후 진행)
- **✅ 말하기 안부 음성도 보호자가 직접 청취 가능**: 대상자 상세 화면에 최근 음성 안부를 재생할 수 있는 플레이어 추가(기존에는 원본 전송 방침만 있고 실제 청취 UI가 없었음)
- **부가 기능**: 저장/다운로드, 음성 기능과의 통합
- **✅ 보관 기간 정책**: 영상편지는 7일이 지나면 스토리지 파일+DB 행이 자동 삭제된다(`api/cleanup-old-letters.ts`, Vercel Cron이 매일 호출). 계속 쌓이면 스토리지 용량이 무한정 늘어나는 문제를 막기 위함 — 근거: 실사용 피드백
- **⚠️ Gemini 영상 분석 (범위 미확정)**: README 회의록에 "Gemini로 영상 분석"이 언급되었으나, 이것이 (a) 영상편지의 정서적 톤을 분석해 보호자에게 요약을 제공하는 기능인지, (b) 어르신의 표정·안색을 분석해 위험도 신호로 쓰려는 것인지 불명확하다. **(b)라면 이미 "버림" 처리한 "AI 안색·표정 진단"과 정면으로 충돌**하므로, 구현 전 팀이 반드시 재논의해 범위를 문서로 확정해야 한다.

### 2.5 초대 링크 온보딩 (예외 처리 포함)
- **트리거**: 보호자가 어르신 등록·지병 선택 완료 후 발급
- **입력**: 어르신 전화번호(문자 발송용 — 이 채널은 이메일 인증 전환과 무관하게 SMS 유지)
- **처리 로직**: 1회용 토큰 생성, 최초 개봉 기기에 종속(다른 기기에서 재사용 불가), 한 번 연결되면 계정처럼 계속 유지
- **출력**: 어르신은 별도 계정 생성 없이 링크 클릭만으로 접속
- **예외 처리**:

| 상황 | 감지 방법 | 처리 |
|---|---|---|
| 휴대폰 분실 | 보호자가 대상자 상세 화면에서 "재초대" 요청 | 기존 토큰 무효화 후 새 1회용 링크 발급, 문자 재발송 |
| 기기 변경(새 폰 구매) | 새 기기에서 기존 링크 접속 시 device_fingerprint 불일치 | 기존 링크는 만료 처리, 보호자가 재초대해야 새 기기에서 연결 |
| 초대 링크 유출/오전달 | 등록되지 않은 기기에서 최초 개봉 시도 | 최초 개봉 기기에만 종속되므로 이후 다른 기기 접근은 자동 차단 |
| 링크 만료 후 미접속 | 발급 후 일정 기간 미개봉 | 보호자에게 "아직 연결되지 않았어요" 안내, 재발송 유도 |

### 2.6 계정 가입 (✅ 4차 개정: 이메일 인증 제거)
- **트리거**: 보호자가 계정 만들기 화면에서 이메일+비밀번호 입력 후 제출
- **처리 로직**: Supabase Auth `signUp(email, password)` — **이메일 인증 없이 즉시 가입·로그인 처리**(Supabase Auth "Confirm email" 설정을 끈 상태를 전제로 함)
- **변경 이유**: Resend를 도메인 인증 없이(`onboarding@resend.dev`) 쓰면 계정 소유자 본인 이메일 외에는 발송이 거부되는 샌드박스 제약이 있어, 3차 개정에서 도입한 OTP 코드 이메일 인증 방식으로는 팀원 본인 외 아무도 가입할 수 없었다(실사용 중 발견). 이메일 소유 검증이 꼭 필요한 단계가 아니므로, 인증 자체를 제거해 이 문제를 근본적으로 없앴다.
- **Resend 현재 상태**: 이 변경으로 앱 내 실제 이메일 발송 코드 경로가 없어져 Resend가 당장은 쓰이지 않는다. `callog.is-a.dev` 무료 서브도메인을 is-a.dev에 신청 중(§6 오픈 이슈 참고) — 도메인 인증이 완료되면 추후 실제 이메일 소유 검증이나 위험 알림 이메일 등에 다시 활용할 수 있다.
- **예외/제약**: 비밀번호 8자 이상. "계정 찾기"(비밀번호 재설정)는 별도 화면 없이 필요 시 Supabase 대시보드에서 수동 처리한다.

## 3. 위험도 판정 로직 요약표

⚠️ **아래 수치는 데모/설명용이며, 실제 서비스 전환 시 전문가 검증이 필요하다** (오픈 이슈 참고). **✅ 다만 고혈압·당뇨병 가중치는 4차 개정에서 동료심사(peer-reviewed) 문헌 검증을 거쳤다** — `Help4/발표 자료/위험도가중치 근거자료.docx` 참고. 검증 결과:
  - 고혈압 ×1.5: 근거등급 A(IPD 메타분석 100만명 등)로 검증 통과, 보고된 효과크기 범위(1.36~2.11)의 보수적 값이라 변경 없음
  - 당뇨병: 기존 ×2.4(임의값)에서 ×2.0으로 조정 — 문서가 "당뇨 가중치는 고혈압보다 높아야 상대 서열이 문헌과 일치한다"고 명시(근거등급 A: INTERHEART OR 2.37 등)
  - 문서는 여러 위험요인을 단순 곱셈으로 결합하면 과대추정된다고 경고하는데, 현재 구현은 카테고리별 점수를 곱셈이 아니라 합산하는 구조라 이미 그 문제를 피하고 있음(추가 조정 불필요)
  - 문서가 다룬 흡연·이상지질혈증·복부비만·가족력은 현재 지병 목록에 아예 없는 항목이라 가중치 조정 범위 밖 — 추가하려면 새 지병 유형·질문 설계가 별도로 필요

**✅ 실제 구현 완료** — `lib/riskScoring.ts`(repo root, Vercel Function에서 호출)가 아래 점수 모델로 계산해 `risk_assessment`/`elder_profile.priority_status`에 실제로 기록한다. 안부 체크 완료 시(`api/assess-risk.ts`)와 음성 분석 완료 시(`api/analyze-voice.ts`) 두 시점에 재계산된다.

- 안부 체크 각 질문에는 category(복약/식사/외출/기분/지병/기타)와 선택지별 severity(정상/경미/심각)가 태그되어 있다(`api/generate-questions.ts`가 Gemini 생성 시 함께 태깅, 고정 문항도 동일하게 태깅됨) — 자유 텍스트를 다시 해석하지 않고 이 태그로 계산한다.
- 선택지 severity별 기본 점수: 정상=0, 경미=1, 심각=2

| 신호 | 조건 | 가중 대상 | 결과 |
|---|---|---|---|
| 복약 누락 | 복약 질문에 정상이 아닌 응답 | 고혈압 보유자 | 점수 ×1.5 |
| 식사 결식 | 식사 질문에 정상이 아닌 응답 | 당뇨병 보유자 | 점수 ×2.0(저혈당 우려) |
| 외출 없음 | 외출 질문에 정상이 아닌 응답 | 관절염 보유자 | 점수 0으로 제외(위험 요인으로 보지 않음) |
| 음성 분석 실패 | `voice_response.analysis_status = 'failed'` | 전체 | +1점("애매한 판정은 위험으로 낮춰 재확인 유도" 원칙) |
| 합산 등급 | 점수 ≥3 / ≥1 / 0 | 전체 | 심각 / 위험 / 안전 |

**✅ 무응답 7시간 자동 알림 구현 완료**(`api/check-no-response.ts`, 위 참고). **아직 미구현(오픈 이슈로 이월)**: 연속 외출 없음(3일) 자동 알림. 음성의 발화속도·침묵비율 기반 개인 기준선 비교도 미구현(§6 오픈 이슈 2번 — Gemini의 정량 지표 신뢰도 검증 전이라 보류).

## 5. 비기능 요구사항

- **접근성**: 글씨 크기 확대 가능, 어르신 눈높이 단어 사용, TTS 지원(AI 음성 기능에 대한 거부감 완화 목적)
- **개인정보 보호**: 개인정보 동의 절차 필수, 안색·표정 등 민감 생체 정보 분석은 원칙적으로 제외(단, Gemini 영상분석 범위 확정 전까지는 재검토 대상)
- **신뢰성**: AI는 "진단"이 아닌 "확인 필요 신호"로만 표현 — 법적/신뢰 리스크 관리
- **보안**: 초대 링크 1회용·기기 종속으로 무단 접근 방지. Supabase/Resend/Gemini API 키는 환경변수로만 관리, 저장소에 커밋 금지
- **비용**: 전면 무료 서비스 — 결제·구독 관련 기능/인프라는 구축하지 않는다

## 6. 오픈 이슈 (기능 관점)

1. **(최우선) Gemini "영상 분석"의 정확한 용도 확정** — 영상편지의 정서적 톤 분석인지, 어르신의 표정·안색 분석("버림" 항목과 충돌)인지 팀이 반드시 재논의해 범위를 문서로 명문화할 것
2. STT 없이 Gemini 단독으로 발화 속도·침묵 비율 등 정량 지표를 안정적으로 추출할 수 있는지 기술 검증 필요 — 불가능하면 보조 STT 병행 여부 결정
3. **✅ 해결(방향 전환)** — 이메일 인증 자체를 제거해 유효시간/재발송 정책 이슈가 해소됨(§2.6 참고). 다만 "계정 찾기"(비밀번호 재설정) 화면이 없어 팀원이 비밀번호를 잊으면 Supabase 대시보드에서 수동으로 재설정해줘야 함 — 필요성이 커지면 별도 화면 추가 검토
4. "관계" 필드 유지 + "성별" 필드 추가(제안)가 실제 데이터 모델·화면에 반영될지 팀 최종 확인 필요
5. 대상자 목록의 우선순위를 자동 산정 등급 그대로 둘지, 사용자가 수동으로 재조정할 수 있게 할지 여부
6. 무응답 임계 시간(7시간), 연속 외출 없음 기준(3일) 등 구체적 파라미터의 근거 자료 필요(현재는 팀 합의 잠정값)
7. **✅ 해결됨 — §3 위험도 판정 로직 실제 연결.** `lib/riskScoring.ts`가 안부 체크·음성 분석 완료 시점에 실제로 `RiskAssessment` 행을 쓰고 `priority_status`를 갱신한다. **✅ 무응답 7시간 자동 감지도 구현 완료**(`api/check-no-response.ts`). 연속 외출 없음 자동 감지·음성 정량 지표 기반 판정은 아직 미구현(위 §3 참고)
8. **✅ 해결됨** — 대상자 상세 화면에 최근 14일 `RiskAssessment` 등급 추이를 인라인 SVG 꺾은선 그래프(`components/TrendChart.tsx`)로 시각화. 기록 없는 날은 결측으로 표시(선을 억지로 잇지 않음)
