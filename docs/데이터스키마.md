# 데이터 스키마 — 장수기록 (팀 헬포)

- 목적: [기능설계서.md](기능설계서.md) §4가 "참고용, 상세 스키마는 별도 문서 필요"로 남겨둔 부분을 구체화
- 범위: 해커톤/코스 단계에 맞는 수준 — 엔티티·필드·관계만 정의. 마이그레이션, 인덱스, 샤딩 등 스케일링 이슈는 다루지 않는다
- 전제: [PRD_통합본.md](PRD_통합본.md)의 **1가족(FamilyAccount) : N인생선배(ElderProfile)** 구조 확정을 반영
- **DB**: Supabase(Postgres) 확정. 아래 엔티티는 각각 하나의 테이블로 구현
- **호칭 안내**: 엔티티/필드명은 기존 영문 식별자(FamilyAccount = 인생 후배 계정, ElderProfile = 인생 선배 프로필)를 유지한다 — 코드 식별자를 바꾸면 혼란이 커서, 서비스 화면에 보이는 한글 명칭만 "인생 선배/인생 후배"로 변경했다.
- **인증 방식 변경**: 전화번호 인증 → **이메일 인증**(Supabase Auth + Resend)으로 전환하며 `FamilyAccount.phone`을 `email`로 변경

## 1. 엔티티 관계 개요

```
FamilyAccount (인생 후배 계정) 1 ──< N  ElderProfile (인생 선배 프로필)
ElderProfile               1 ──< N  ElderCondition (지병목록)
ElderProfile               1 ──< N  DailyCheckIn (일일응답기록)
DailyCheckIn               1 ──< 1  VoiceResponse (음성응답, 선택)
ElderProfile               1 ──< N  RiskAssessment (위험도이력)
FamilyAccount               1 ──< N  InviteLink (초대링크)
FamilyAccount / ElderProfile  ──< N  VideoLetter (영상편지, 발신·수신 다형 참조)
```

## 2. 엔티티별 필드

### FamilyAccount (인생 후배 계정)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 계정 고유 식별자 (Supabase Auth user id) |
| email | string | **이메일**(로그인·인증용, 전화번호에서 변경) |
| password_hash | string | 비밀번호 해시 (Supabase Auth가 관리) |
| auto_login | boolean | 자동 로그인 여부 |
| created_at | datetime | 가입일 |

### ElderProfile (인생 선배 프로필)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 인생 선배 고유 식별자 |
| family_account_id | string (FK → FamilyAccount) | 소속 가족계정 (1가족:N인생선배) |
| name | string | 성함 |
| birth_date | date | 생년월일 (화면에는 계산된 나이로 표시) |
| relationship | string | 나와의 관계 (예: 어머니) — 1차 유지 필드 |
| gender | string, nullable | 성별 (제안 필드, 팀 최종 확인 대기) |
| nickname | string, nullable | 대상자 목록용 별명 |
| checkin_time | time | 안부 묻는 시각 |
| priority_status | enum(안전, 위험, 심각) | 현재 우선순위 상태 (RiskAssessment 최신값에서 파생) |
| created_at | datetime | 등록일 |

### ElderCondition (지병목록)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| elder_profile_id | string (FK → ElderProfile) | 대상 인생 선배 |
| condition_type | enum | 사전 정의 지병 카테고리(고혈압, 당뇨병, 관절염 등) |
| custom_text | string, nullable | 직접 입력한 지병명(사전 정의 목록에 없을 경우) |

### DailyCheckIn (일일응답기록)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| elder_profile_id | string (FK → ElderProfile) | 대상 인생 선배 |
| date | date | 응답 날짜 |
| answers | json | 문항별 선택형 응답(복약/식사/외출 등) |
| condition_selfreport | enum | 오늘의 컨디션 선택 |
| skipped | boolean | 오늘 건너뛰기 여부 |

### VoiceResponse (음성응답) — Gemini 기반으로 변경
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| daily_checkin_id | string (FK → DailyCheckIn) | 연결된 일일응답기록 |
| audio_url | string | 원본 음성 파일 경로 (Supabase Storage) |
| transcript | string | **Gemini 분석 결과 텍스트** (기존 STT 변환 텍스트에서 출처 변경, 필드 의미는 동일) |
| speech_rate | float | 발화 속도(어절수/분) — Gemini 응답에서 추출 가능한지 검증 필요([기능설계서.md](기능설계서.md) 오픈 이슈) |
| silence_ratio | float | 침묵 비율 — 위와 동일하게 검증 필요 |
| response_latency_ms | int | 질문 표시~응답 시작까지 반응 지연 (클라이언트에서 측정, Gemini와 무관) |
| shared_with_family | boolean | 인생 후배에게 원본 전송 여부(기본 true) |

### RiskAssessment (위험도이력)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| elder_profile_id | string (FK → ElderProfile) | 대상 인생 선배 |
| date | date | 산정 일자 |
| level | enum(안전, 위험, 심각) | 위험도 등급 |
| reason | string | 사유 문구(예: "일곱 시간 동안 대답이 없습니다") |
| triggered_by | json | 근거가 된 신호(무응답시간, 복약누락, 외출없음 등) |
| family_action | enum(없음, 전화함, 확인함), nullable | 인생 후배 대응 상태 |

### VideoLetter (영상편지) — Gemini 영상 분석 필드는 범위 미확정으로 보류
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| sender_type | enum(family, elder) | 발신자 유형 |
| sender_id | string | 발신자 ID (FamilyAccount 또는 ElderProfile) |
| receiver_type | enum(family, elder) | 수신자 유형 |
| receiver_id | string | 수신자 ID |
| title | string | 한 줄 제목 |
| video_url | string | 영상 파일 경로 (Supabase Storage) |
| sent_at | datetime | 발신 시각 |
| viewed_at | datetime, nullable | 열람 시각 |
| unlock_condition | string | 열람 조건(예: "해당일 안부체크 완료 후") |

⚠️ Gemini 영상 분석 결과를 저장할 필드(예: `analysis_summary`)는 **아직 추가하지 않았다** — 분석 목적(정서적 톤 vs 안색·표정)이 확정되기 전까지 스키마를 섣불리 늘리지 않기 위함이다. 범위가 정해지면 이 테이블에 필드를 추가한다.

### InviteLink (초대링크)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (PK) | 식별자 |
| family_account_id | string (FK → FamilyAccount) | 발급 주체 |
| elder_profile_id | string (FK → ElderProfile) | 대상 인생 선배 |
| token | string | 1회용 토큰 |
| device_fingerprint | string, nullable | 최초 개봉 기기 식별자(기기 종속) |
| expires_at | datetime | 만료 시각/조건 |
| used_at | datetime, nullable | 사용(개봉) 시각 |

## 3. 미확정 항목 (오픈 이슈와 연동)

- `ElderProfile.gender`: 팀 최종 확인 전까지 nullable로 유지, 확정되면 필수화 여부 재검토
- `RiskAssessment.triggered_by`의 가중치 수치(1.5배, 2.4배 등)는 [기능설계서.md](기능설계서.md)의 위험가중치 표를 참조하되, 잠정값임을 코드 주석에도 명시할 것
- `VoiceResponse.speech_rate`/`silence_ratio`를 Gemini 응답에서 실제로 안정적으로 뽑아낼 수 있는지 미검증 — 안 되면 필드 정의 자체를 수정해야 할 수 있음
- `VideoLetter`의 Gemini 영상 분석 결과 저장 필드는 분석 목적이 확정된 뒤 추가
